# 产品路线图

只保留待办、待评估方向与待验收项；已实现的行为以代码和开发指南为准。

## 产品目标

让家人用很少的操作看清今天的安排、自己的分工，并记录共享信息。管理员维护属于低频操作，日常首页优先服务安排、任务和笔记。

## 待办

- **笔记置顶**：补齐持久化、API 和权限测试，再提供常用信息入口。
- **家庭首次使用引导**：自行创建家庭后引导邀请家人、添加第一条任务，可跳过；接受邀请后直接进入家庭今日页。

两项分别评估和验收，不捆绑推进。布局和表单的通用原则维护在 [design.md](design.md)，不再保存已完成的改造清单。

## 待验收

现有自动化与局部设备记录不能替代以下场景；重新验收时记录安装包版本、设备、权限和供电条件：

- **通用原生界面**：Android / iOS 大字体、软键盘避让、系统返回、日期选择、长内容与下拉刷新。
- **Android 通知与闹铃**：已有小米 Android 13 debug 包的局部实测。继续确认允许锁屏显示、后台弹出且关闭省电限制后的亮屏与页面展示；拔掉数据线、勿扰、划掉应用、重启、自启动限制下的行为；通知冷启动和「查看详情」；稍后再响到点后的触发，以及服务被系统停止后通知和按钮的清理。
- **iOS 本地提醒**：权限、到点展示、应用退出与设备重启后的排程、点击通知冷启动、容量边界。
- **农历与生日**：真机上月历农历小字在大字体和窄屏下的排版；「显示农历」开关在应用重启后保留；生日的「提醒我」在当天参考时间到点。
- **App 语音输入**：真实 M4A 转写、首次与永久拒绝权限、短录音、来电与后台切换，以及取消后资源释放。Web 的真实百炼转写记录不能代替这些检查。
- **真实对话模型**：用固定中文场景验证工具往返、跨日程/任务/笔记查询、共享权限、冲突和批量部分失败；记录最终数据正确性、错误写入、依据完整性与延迟。假提供商测试不证明供应商兼容性。
- **家庭可用性**：观察查看安排、创建采购任务、找家人日程、共享笔记与邀请的成功率、耗时和误触。先建立真实基线，再定改善目标；少量家庭样本用于发现问题，不作为统计显著性结论。

## 待评估方向

- 提醒后台定期同步，只作为打开 App 同步的补充，需评估厂商系统限制。
- 助手模型能力标记、用量上限，以及查询过滤和分页下推数据库；按真实规模与失败样本决定优先级。
- 语音的人名词表或流式预览：分别评估额外数据发送与新接口成本。
- 日文界面与和历：界面目前只有中文，文字写在约 136 个客户端文件里，API 错误提示和助手提示词也是中文。日文需要先引入多语言框架、逐页迁移，并先定语言按账户还是按设备、助手用什么语言回答。和历（年号、日本节假日）可以独立先做，规模接近「显示农历」。

## 非目标

不随视觉改造改变权限、日期和重复规则语义。当前不引入服务端推送、Web 通知、聊天、积分或位置跟踪。提醒采用本机排程，其能力与代价见 [开发指南](development.md#提醒与闹铃)。
