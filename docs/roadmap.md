# 产品路线图

本文只记录**尚未实现**的产品意图、非目标与验收目标。已经落地的部分以代码为准，不在此重复。

来源为 2026-09-14 的家庭协作体验改版方案，各条已对照当前实现逐项核对（2026-09-22）。完整的原始方案、现状取舍表与页面线框保留在 git 历史中的 `docs/product-experience-redesign.md`。视觉与组件规范见 [前端设计规范](design.md)。

## 产品目标

让家庭成员用很少的操作回答三个问题：今天有什么安排、哪些事需要我处理、如何把一件事交代给家人。移动端优先，保留温暖克制的视觉风格。

主要场景：早上看接送和预约；临时记录采购、家务；查看家人的分工；保存长期共用的信息。管理员操作属于低频维护，不应占据日常首页。

## 非目标

保留现有服务端权限、日期语义和重复规则语义 —— 视觉或交互改版不得顺带改变它们。不引入通知、聊天、积分或位置跟踪等新业务。

## P1

| 项 | 内容 | 现状 |
| --- | --- | --- |
| 未设日期任务拆出「待安排」 | 现在没有截止时间的任务被归入今日待办，把「无日期」显示成「今天到期」。拆分要同步调整分组与回归测试，不能暗改业务含义。 | 未实现 |

| 日历周视图 | 移动端默认改为周条加当日列表，月历可展开；切换月份保留选中日期的明确提示，并提供「回到今天」。从选中日期创建时带入日期，跨日事件展示结束日期。 | 未实现 |
| 笔记搜索与排序 | 标题搜索、按最近更新排序；空态说明适合记录什么（采购清单、旅行计划、家电说明）并给出直接创建入口。 | 已实现。搜索在客户端按标题过滤（`src/features/notes/note-search.ts`），列表改为 `updatedAt` 倒序；正文不参与匹配 |
| 创建表单渐进展开 | 必填信息先出现，负责人、标签、重复与高级时间设置按需展开，当前保存家庭始终可见。 | 未实现（草稿保留与离开保护已实现） |

每项独立验收后再扩展，不合并推进。

## 验收目标

- 进入家庭到看见今日内容：零次额外点击。
- 主模块之间切换：一次点击。
- 从今日进入任一创建表单：一次点击。
- 创建耗时、任务完成率、次周家庭活跃率需要先建立真实基线再定目标，不能把设计推断当作已验证的效果。

## 产品验证建议

找 5 个家庭，各完成「查看今天安排、创建采购任务、找到家人的日程、共享笔记、邀请成员」五个任务，记录首次成功率、耗时、误触和求助点。该样本用于发现可用性问题，不足以证明统计显著的改善。
