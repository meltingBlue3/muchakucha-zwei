# 前端设计规范

本规范用于新增页面、调整组件和审查视觉改动，约定跨页面的设计原则与交互边界。Android、iOS 和 Web 分别适配触控、键盘和阅读场景；页面功能由产品需求决定。

[theme.ts](../apps/client/src/ui/theme.ts) 是颜色、字体、间距、圆角、尺寸和动效参数的唯一实现来源；本文保留用途与选择规则。组件接口和默认行为查 [共享 UI](../apps/client/src/ui/)，平台能力查 [平台适配层](../apps/client/src/platform/)。用户明确提出的设计调整优先于本文。

## 设计方向与信息层级

安静的工具，带一点家庭的温度。以「纸 · 墨 · 朱」为基调，用字号对比、留白和对齐组织信息；同类内容合成清单，以细线分隔，减少装饰。

- 让布局说明信息关系，避免不必要的次级标签和说明文字。
- 相关元素靠近，独立内容组留出更大间距；同一页面保持一致的对齐线。
- 清单标题用常规字重，半粗体用于标签、按钮和少数强调。操作名称与关键状态保持可读，长内容按性质换行或截断。
- 窄屏与宽屏分别组织空间：窄屏用完整页面和按需展开的面板，宽屏利用侧栏、阅读区和详情区；正文保持适合阅读的宽度。
- 参考 Things、Apple 提醒事项等产品的层级与克制；参考资料用于理解方法，具体设计仍遵循本规范。

## 色彩、文字与布局

### 色彩与表面

| 用途 | 规则 |
| --- | --- |
| 页面与内容 | 纸色 `canvas` 承载白色 `surface` 面板，面板之间以留白区分；阴影用于窗口、菜单、创建按钮和浮动提示 |
| 正文与主操作 | 正文用 `ink`，次要文字用 `inkMuted`；主操作用墨色 `primary` |
| 朱色 | `accent` 用于今天、现在线、逾期、紧急和正在录音的指示；Web 键盘焦点用 `focusRing`。普通操作使用墨色 |
| 边界 | 输入框与勾选圈等必要边界用 `border`，次要按钮描边用 `outline`，清单细线用 `separator` |
| 状态 | 选中、按下、禁用、成功与危险状态使用对应语义 token；浅色状态底使用对应的 `Soft` token |

朱色浅底上的文字用 `accentStrong`；`inkFaint` 只用于纸色或白色背景，其他背景改用对比度合适的文字 token。月历里的农历小字用 `lunarDay` 字号：节日、节气和农历月初一的月名用 `ink`，其余农历日用 `inkFaint`，不用朱色。家人颜色按用户 id 固定分配，标签使用内容自身的颜色；家人配色与标签预设色均不含朱色。

### 文字与控件

通过 `Text`、`Heading` 的语义变体表达用途：`display` 用于主页面标题，`heading` 用于窗口标题，`section` 用于分组；正文用 `body`，辅助信息用 `bodySm` / `meta`，字段标签用 `label`。中文跟随系统字体，时间、日期和数量用 `time` / `numeral` 的等宽数字。标题的读屏层级跟随内容结构，窗口内的分组标题在窗口标题之下；保留字体缩放能力，通过调整布局容纳大字。

按钮为胶囊形：主按钮墨色填充、次要按钮白底描边、危险按钮使用 `destructive`。标题栏和行内次要操作用紧凑按钮，表单提交与确认按钮保持标准尺寸；视觉尺寸与触控区域分别处理，触控区域遵循 `controlSizes.touchTarget`。图标使用 Lucide 和统一线宽，同类动作使用同一图标，图标按钮提供明确的可访问名称。

纯文字链接带下划线。链接和标签胶囊按下时变淡，行与图标按钮改变背景色，实心按钮使用对应的按下色。Web 键盘焦点显示朱色描边，文字输入框保留墨色边框；裁切容器内的行使用 [内侧焦点框](../apps/client/src/platform/focus-ring/focus-ring.web.ts)，避免描边被截断。

### 布局

Web 宽度 ≥ 1024px 使用纸色侧栏与白色工作区：工作区外边距 8（贴侧栏一侧为 0）、描边 1、圆角 12，统一页眉高 56；标题、摘要和页面操作放在页眉内。页面正文按各自分栏模板铺满剩余空间，清单不再限制为居中的窄列。布局数值由 `theme.layout` 管理，页面规格见 [桌面重设计](desktop-redesign.md)。

- 1024–1279px：侧栏为 64px 图标栏，详情栏 360px；今日的「接下来」移至待办下方。
- 1280–1599px：侧栏 248px，详情栏 400px。
- ≥1600px：详情栏随宽度增长至 520px；任务清单最宽 880px，笔记正文最宽 680px。
- 小于 1024px 和原生端继续使用原有布局。仅宽屏且使用精细指针时，按钮 32px、任务行 40px；触控设备保留 48px 目标。
- 宽屏清单（任务、笔记、标签、重复安排、今日待办）用通栏行：行与细线贯穿整栏，文字距栏边 20；优先级、今天等用小标签 `Chip`。视图切换（任务状态、重复安排类型）紧跟页标题，搜索、筛选和创建留在页眉右侧。详情栏标题栏在阅读时是弱化的栏名加图标按钮（编辑为铅笔），在表单中显示表单名。助手的三栏各有 56px 栏头，不再使用共享页眉。
- 宽屏侧栏顶部有收起按钮（记在本浏览器；1280 以下默认收成图标栏）和搜索入口；`Ctrl K`（Mac 上 ⌘K）在任意位置打开搜索面板，按标题和正文找页面、任务、日程和笔记，结果在各自栏目里打开。「今日」旁是今天的日程和待办数，「任务」旁的朱色数字是逾期数。详情栏里的表单可用 `Ctrl Enter` 提交，底栏左侧写明这个快捷键。登录和注册在宽屏左侧是产品介绍和一张今日小样，右侧是浮起的表单面板。
- 宽屏的「创建」菜单是按钮下方的锚定小菜单，不加遮罩。笔记只在笔记列表旁用宽阅读区；从其他页面新建或打开时，和任务、日程一样在右侧详情栏里。今日页只保留和打开内容相关的栏：日程留时间安排和「接下来」，任务留时间安排和待办（从「未来 7 天」打开的任务留「接下来」），笔记只留时间安排，详情栏占两栏的位置（约 700）。详情栏打开时淡入并从右侧滑入 16px，栏的收起和展开随宽度过渡（200ms）；在条目间切换不重播；减少动态效果时只淡入。关闭按钮是带浅底的圆形墨色 ×。

详情栏是有名称的 `region`，不设遮罩、不陷入焦点。鼠标打开时保留焦点，键盘打开时聚焦栏标题；只有焦点位于详情栏内时 Escape 才关闭，关闭后返回触发行。清单里的条目先以阅读状态打开（任务、日程、笔记、重复安排都一样）：标题栏的铅笔（手机上是「编辑」）进入编辑，保存或取消后回到详情；结束、删除这类收尾操作放在详情里。编辑中点清单里的另一项时，没有改动就直接切换；有改动则用居中的提示窗「修改还没有保存」询问，详情栏里的编辑内容保持原样。有草稿的编辑器提供「保留草稿并切换」，标签这类不存草稿的编辑提供「放弃修改并切换」。日期选择使用锚定弹层。独立删除确认、账户和家庭设置确认继续使用居中 `dialog`。

- 家庭页面复用 `HouseholdScreen`，个人页面复用 `AccountScreen`；底栏、侧栏、安全区、边距和键盘空间由共享布局负责，导航断点使用 `theme.layout`。
- 手机主导航使用底栏，宽屏使用侧栏；子页面在手机上保留返回入口并隐藏底栏，宽屏保留侧栏。主页面标题区使用 `PageIntro`，顶栏不重复标题；创建入口在手机右下角、宽屏工作区页眉右侧。
- 同类条目放进 `ListGroup`，以 `ListRow` 和细线组织；组名与数量用 `GroupLabel`。行两侧控件对齐标题行，时间、色条与勾选圈使用一致的列宽；行主体与独立操作并列，避免交互控件嵌套。
- 手机上的去处和选项用菜单行；条目编辑、删除收进「…」菜单，单个次要操作放在它所说明的行内，分组操作放在分组标题旁。隐藏无权限操作，菜单为空时隐藏入口。
- 详情使用 `DetailPanel` / `DetailField`，一项一行、左名右值，长值换行；编辑入口放在窗口或详情栏标题栏。

## 界面用语

同一概念在可见文字和读屏名称里使用同一个词；代码里的技术名称不受影响。

| 概念 | 统一用语 |
| --- | --- |
| 日历中的一项安排 | 日程；「日历」只指页面 |
| 自动重复的日程或任务 | 重复、重复安排；频率设置称「重复规则」 |
| 家庭最高角色与身份交接 | 所有者、转移所有权 |
| 创建与编辑提交 | 创建、保存；上下文已明确时省略对象名称 |
| 个人的到点提示 | 提醒；表单与详情字段称「提醒我」；系统通知权限称「通知」 |
| 按农历的日期与重复 | 农历十月十五、每年农历十月十五；十一月、十二月称冬月、腊月 |
| 生日系列与其页面 | 生日、家人生日；创建入口称「添加生日」 |

计数使用全角括号，如「逾期任务（3）」。日期复用 [日期工具](../apps/client/src/ui/date-values.ts)，显示为「9月27日」「9月27日 14:30」，非今年加年份；日期选择器保留完整年份。分组已说明日期时，行内只写时间。月历、周视图、日期选择器与重复星期均从周一开始。

## 组件选择与关键交互边界

优先组合已有组件；重复的视觉结构提取到共享层，业务组件负责领域内容。路由和业务文件引用主题 token，新增 token 按用途命名。

| 需求 | 优先使用 |
| --- | --- |
| 页面框架与标题 | `HouseholdScreen`、`AccountScreen`、`AppShell`、`PageIntro` |
| 文字、按钮、输入与反馈 | [primitives.tsx](../apps/client/src/ui/primitives.tsx) |
| 清单与设置分组 | [ListGroup / ListRow](../apps/client/src/ui/list-group.tsx)、`SettingsSection` / `SettingsRows` |
| 搜索、筛选与标签 | `SearchField`、`FilterOptions`、`FilterActions`、`LabelTags` / `LabelChip` |
| 家人、日程与任务标记 | `MemberAvatar` / `AvatarStack`、`EventBar`、`CheckCircle`、`NowMarker` |
| 弹窗、路由窗口与步骤 | [AppDialog](../apps/client/src/ui/app-dialog.tsx)、[RouteWindow](../apps/client/src/ui/route-window.tsx)、[useWindowStep](../apps/client/src/ui/window-step.ts) |
| 表单、确认与条目操作 | `FormActions`、`ConfirmActions`、`CardActionsMenu` |
| 编辑行与详情字段 | [compose-rows.tsx](../apps/client/src/ui/compose-rows.tsx)、[DetailPanel / DetailField](../apps/client/src/ui/detail-fields.tsx) |
| 个人提醒与家庭归属 | `ReminderField` / `ReminderDetailField`、`HouseholdContextNote` |
| 加载、失败、空数据与撤销提示 | `LoadingState`、`LoadError`、`EmptyState`、[ActionNotice](../apps/client/src/ui/action-notice.tsx) |

### 弹窗与选择

容器、遮罩、标题、关闭入口和焦点管理统一交给 `AppDialog`；路由窗口复用 `RouteWindow`。共同外观通过基础组件修改，并验证所有使用场景。新建与编辑窗口用 `HouseholdContextNote` 说明保存到哪个家庭。

| 类型 | 宽屏 | 窄屏 |
| --- | --- | --- |
| 任务、日程、笔记与重复安排的阅读 / 编辑窗口 | 常驻详情栏，无遮罩，列表保持可操作，当前条目有选中标记；笔记占据完整阅读区 | 最窄屏使用全屏编辑面板，左上关闭、右上主操作；中间宽度居中，断点由主题定义 |
| 账户与设置 | 个人资料原位编辑，选项用锚定弹层；退出、重命名与邀请等独立窗口居中 | 居中，沿用对应窗口尺寸 |
| 独立确认窗口 | 标准尺寸居中 | 标准尺寸居中 |
| 助手操作、模型选择与查询依据 | 操作内容可在工作区右栏展示；弹层使用共享容器 | 底部面板 |

- 编辑内的步骤与确认在原窗口切换，保留编辑内容；确认使用标准尺寸，详情栏内的确认继续留在该栏。确认放在引起它的地方：栏内的保存、结束、删除在栏内确认；从清单菜单直接发起的删除、在清单里点另一项引起的未保存询问，都用居中提示窗。
- 固定选项用摘要行打开步骤选择：单选选中即生效，多选用「完成」确认。步骤内不再嵌套步骤；其中的日期字段可叠加一个标准 `AppDialog`，这是叠加遮罩的唯一例外，只有最上层弹窗响应键盘。
- 日期选择沿用平台方案：Android 使用系统 Material 3 对话框，时间跟随手机的 12/24 小时设置；iOS 使用原生日历或滚轮；Web 使用 [共享选择面板](../apps/client/src/ui/picker-panels.tsx)。日期标记统一为墨色实心圆表示选中、朱色表示今天，两者重合时为朱色实心圆。
- 全屏弹层使用 `DialogBackdrop` 的模糊与浅遮罩，常驻详情栏除外；锚定菜单使用透明关闭层。系统原生提示与锚定菜单保持各自交互类型。
- 确认按钮安全选项在前、提交在后，放不下时纵向排列；不可逆或收回权限的提交使用危险样式，多步确认只在最后一步使用。单输入框设置窗口保留一个提交按钮，取消走关闭入口。

### 状态与恢复

- 覆盖组件适用的默认、按下、选中、禁用、加载、成功和失败状态；加载时保留操作文字，避免重复提交。状态同时提供文字或形状信息：逾期、紧急写明状态，已完成加删除线并写明「已完成」。
- 加载失败就地说明并提供重试，保留已有内容；提交失败保留输入与恢复入口；未知数量不显示为零。空状态与页面文字左对齐，可附一个下一步操作。
- 收件箱摘要打开详情，接受、拒绝等动作独立触发；后台更新保留已有消息，移动端提供下拉刷新。缺少服务端已读状态时，待处理数量只能称为「待处理」，不能称为「未读」。
- 撤销提示保持可操作，不定时消失；点击页面其他位置时等手势结束后关闭，或离开页面时关闭，避免列表重排影响当前点击。

## 变更与视觉验收

先确定改动属于页面组合、组件能力还是全局主题，再定位共享实现。通用设计决策改变时同步更新本文、实现和相关检查；局部功能细节留在对应实现中。发现规范与实现不一致时，先确认是否属于本次需求，再校正相关部分。

视觉验收检查：

- 颜色与控件用途符合上述规则，主题参数与共享组件保持复用，同类内容的层级、对齐和密度一致。
- 受影响页面在 320、390、1440 宽度下无水平溢出，导航、表单和主要操作可达；长内容、大字、空数据、加载与失败状态均可用。
- 触控目标、读屏名称、状态语义、键盘焦点和对比度可用。Web 交互变更另读 [无障碍约定](agent/web-accessibility.md)。
- 共享组件变更覆盖受影响页面，布局变更检查实际渲染与截图；弹窗基础组件变更同时回归账户和家庭设置窗口，检查容器、标题、关闭入口与背景样式。
- 原生布局或平台能力变更进行设备验收；Web 检查不能替代真机证据。测试选择、执行与证据报告遵循 [testing.md](agent/testing.md)。

[token 检查](../apps/client/src/ui/__tests__/token-static-test.ts) 与 [对比度检查](../apps/client/src/ui/__tests__/contrast-test.ts) 约束设计实现，保持其断言强度。纯文档修改检查内容、差异和链接即可。

设计依据：[Apple Typography](https://developer.apple.com/design/human-interface-guidelines/typography) 与 [Layout](https://developer.apple.com/design/human-interface-guidelines/layout) 支持清晰层级、字体缩放和自适应布局；[Things](https://culturedcode.com/things/features/) 启发日程与任务集中呈现；[W3C 颜色使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color) 与 [对比度](https://www.w3.org/TR/WCAG22/#contrast-minimum) 支持状态冗余表达和可读性。这些资料提供方法，具体视觉取值属于本项目决策。

未完成的产品意图与验收事项见 [路线图](roadmap.md)。
