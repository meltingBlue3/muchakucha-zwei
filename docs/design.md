# 前端设计规范

本规范用于新增页面、调整组件和审查视觉改动，约定跨页面的设计原则与交互边界。Android、iOS 和 Web 分别适配触控、键盘和阅读场景；页面功能由产品需求决定。

[theme.ts](../apps/client/src/ui/theme.ts) 是颜色、字体、间距、圆角、尺寸和动效参数的唯一实现来源；本文保留用途与选择规则。组件接口和默认行为查 [共享 UI](../apps/client/src/ui/)，平台能力查 [平台适配层](../apps/client/src/platform/)。用户明确提出的设计调整优先于本文。

## 设计方向与信息层级

安静的工具，带一点家庭的温度。以「纸 · 墨 · 朱」为基调，用字号对比、留白和对齐组织信息；同类内容合成清单，以细线分隔，减少装饰。

- 让布局说明信息关系，避免不必要的次级标签和说明文字。
- 相关元素靠近，独立内容组留出更大间距；同一页面保持一致的对齐线。
- 清单标题用常规字重，半粗体用于标签、按钮和少数强调。操作名称与关键状态保持可读，长内容按性质换行或截断。
- 窄屏与宽屏分别组织空间：窄屏用完整页面和按需展开的面板，宽屏利用侧栏、阅读区和详情区；正文保持适合阅读的宽度。
- 参考 Things、Apple 提醒事项等产品的层级与克制；参考资料用于理解方法，具体设计仍遵循本规范。

## 色彩、文字与布局

### 色彩与表面

| 用途 | 规则 |
| --- | --- |
| 页面与内容 | 纸色 `canvas` 承载白色 `surface` 面板，面板之间以留白区分；阴影用于窗口、菜单、创建按钮和浮动提示 |
| 正文与主操作 | 正文用 `ink`，次要文字用 `inkMuted`；主操作用墨色 `primary` |
| 朱色 | `accent` 用于今天、日本的祝日、现在线、逾期、紧急和正在录音的指示；Web 键盘焦点用 `focusRing`。普通操作使用墨色 |
| 边界 | 输入框与勾选圈等必要边界用 `border`，次要按钮描边用 `outline`，清单细线用 `separator` |
| 状态 | 选中、按下、禁用、成功与危险状态使用对应语义 token；浅色状态底使用对应的 `Soft` token |

朱色浅底上的文字用 `accentStrong`；`inkFaint` 只用于纸色或白色背景，其他背景改用对比度合适的文字 token。月历里的农历小字用 `lunarDay` 字号：节日、节气和农历月初一的月名用 `ink`，其余农历日用 `inkFaint`，不用朱色。打开「显示日本的祝日与和历」后，祝日的日期数字和祝日名用朱色，祝日名取代当天的农历小字，超过四个字的写短名（建国記念、休日）；周日不标红。年号写在月份标题旁，用 `inkFaint`。家人颜色按用户 id 固定分配，标签使用内容自身的颜色；家人配色与标签预设色均不含朱色。

### 文字与控件

通过 `Text`、`Heading` 的语义变体表达用途：`display` 用于主页面标题，`heading` 用于窗口标题，`section` 用于分组；正文用 `body`，辅助信息用 `bodySm` / `meta`，字段标签用 `label`。中文跟随系统字体，时间、日期和数量用 `time` / `numeral` 的等宽数字。标题的读屏层级跟随内容结构，窗口内的分组标题在窗口标题之下；保留字体缩放能力，通过调整布局容纳大字。

按钮为胶囊形：主按钮墨色填充、次要按钮白底描边、危险按钮使用 `destructive`。标题栏和行内次要操作用紧凑按钮，表单提交与确认按钮保持标准尺寸；视觉尺寸与触控区域分别处理，触控区域遵循 `controlSizes.touchTarget`。图标使用 Lucide 和统一线宽，同类动作使用同一图标，图标按钮提供明确的可访问名称。

Web 上系统画占位滚动条时（如 Windows），改为透明轨道上的细墨色半透明滑块，没有箭头，悬停或拖动时变粗、变深；尺寸和颜色取 `theme.scrollbar` 与 `scrollbarThumb`。覆盖式滚动条（macOS 默认、手机）和原生端保持系统样式。

纯文字链接带下划线。链接和标签胶囊按下时变淡，行与图标按钮改变背景色，实心按钮使用对应的按下色。Web 键盘焦点显示朱色描边，文字输入框保留墨色边框；裁切容器内的行使用 [内侧焦点框](../apps/client/src/platform/focus-ring/focus-ring.web.ts)，避免描边被截断。

### 布局

Web 宽度 ≥ 1024px 使用纸色侧栏与白色工作区：工作区外边距 8（贴侧栏一侧为 0）、描边 1、圆角 12，统一页眉高 56；标题、摘要和页面操作放在页眉内。页面正文按各自分栏模板铺满剩余空间，清单不再限制为居中的窄列。布局数值由 `theme.layout` 管理，各页的分栏与页眉见下文「宽屏页面」。

- 1024–1279px：侧栏为 64px 图标栏，详情栏 360px；今日的「接下来」移至待办下方。
- 1280–1599px：侧栏 248px，详情栏 400px。
- ≥1600px：详情栏随宽度增长至 520px；笔记正文最宽 680px。任务清单和其他清单一样铺满工作区，详情栏打开时让出它的宽度。
- 小于 1024px 和原生端继续使用原有布局。仅宽屏且使用精细指针时，按钮 32px、任务行 40px；触控设备保留 48px 目标。
- 宽屏上的清单一律用通栏行，新加的清单页也一样：`ListGroup` 与 `GroupLabel` 加 `flush`，行与细线贯穿整栏，文字距栏边 20。优先级和紧急用小标签 `Chip`，详情栏和日期标题旁的今天也用朱色 `Chip`；清单日期列里的今天和逾期写成朱色文字。详情栏标题栏在阅读时是弱化的栏名加图标按钮（编辑为铅笔），在表单中显示表单名。助手的三栏各有 56px 栏头，不再使用共享页眉。
- 宽屏侧栏顶部有收起按钮（记在本浏览器；1280 以下默认收成图标栏）和搜索入口；`Ctrl K`（Mac 上 ⌘K）在任意位置打开搜索面板，按标题和正文找页面、任务、日程和笔记，结果在各自栏目里打开。「今日」旁是今天的日程和待办数，「任务」旁的朱色数字是逾期数。详情栏里的表单可用 `Ctrl Enter` 提交，底栏左侧写明这个快捷键；编辑已有的任务、日程和标签时，这个位置换成「删除任务」「删除日程」「删除标签」，快捷键照常可用。登录和注册在宽屏左侧是产品介绍和一张今日小样，右侧是浮起的表单面板。
- 宽屏的「创建」菜单是按钮下方的锚定小菜单，不加遮罩。笔记只在笔记列表旁用宽阅读区；从其他页面新建或打开时，和任务、日程一样在右侧详情栏里。今日页只保留和打开内容相关的栏：日程留时间安排和「接下来」，任务留时间安排和待办（从「未来 7 天」打开的任务留「接下来」），笔记只留时间安排，详情栏占两栏的位置（约 700）。详情栏打开时淡入并从右侧滑入 16px，栏的收起和展开随宽度过渡（200ms）；在条目间切换不重播；减少动态效果时只淡入。关闭按钮是带浅底的圆形墨色 ×。

详情栏是有名称的 `region`，不设遮罩、不陷入焦点。鼠标打开时保留焦点，键盘打开时聚焦栏标题；只有焦点位于详情栏内时 Escape 才关闭，关闭后返回触发行。清单里的条目先以阅读状态打开（任务、日程、重复安排都一样；笔记例外，打开就能写，见下文「笔记」）：标题栏的铅笔（手机上是「编辑」）进入编辑，保存或取消后回到详情；结束、删除这类收尾操作放在详情栏底栏左侧，如「结束此重复」「删除日程」，只在有权限时出现。编辑中点清单里的另一项时，没有改动就直接切换；有改动则用居中的提示窗「修改还没有保存」询问，详情栏里的编辑内容保持原样（笔记不问，切换和关闭前先保存）。有草稿的编辑器提供「保留草稿并切换」，标签这类不存草稿的编辑提供「放弃修改并切换」。日期选择使用锚定弹层。独立删除确认、账户和家庭设置确认继续使用居中 `dialog`。

- 家庭页面复用 `HouseholdScreen`，个人页面复用 `AccountScreen`；底栏、侧栏、安全区、边距和键盘空间由共享布局负责，导航断点使用 `theme.layout`。
- 手机主导航使用底栏，宽屏使用侧栏；子页面在手机上保留返回入口并隐藏底栏，宽屏保留侧栏。主页面和家庭子页面的标题区都使用 `PageIntro`，顶栏不重复标题；页标题不折行，和页面操作放不进一行时，操作换到标题下一行并靠右；创建入口交给 `HouseholdScreen` 的 `floatingAction`（`FloatingCreateButton`），手机上在右下角，宽屏上在工作区页眉右侧。
- 同类条目放进 `ListGroup`，以 `ListRow` 和细线组织；组名与数量用 `GroupLabel`。行两侧控件对齐标题行，时间、色条与勾选圈使用一致的列宽；行主体与独立操作并列，避免交互控件嵌套。
- 手机上的去处和选项用菜单行；条目编辑、删除收进「…」菜单，单个次要操作放在它所说明的行内，分组操作放在分组标题旁。隐藏无权限操作，菜单为空时隐藏入口。
- 个人的页面在手机上从头像菜单进入，宽屏从个人中心的二级导航进入，两处列出同样的去处。宽屏已有家庭时侧栏就是家庭的入口，二级导航不再列「我的家庭」。账户的资料放在「个人资料」，只影响这台设备的选项（语言、日历显示）放在「设置」，不混在一页。
- 详情使用 `DetailPanel` / `DetailField`，一项一行、左名右值，长值换行；编辑入口放在窗口或详情栏标题栏。

### 宽屏页面

各页的分栏和页眉按下表组合，宽度取 `theme.layout`。新页面先找最接近的同类页面，照它的框架搭：清单页参照重复安排、标签管理或家人生日，设置类页面参照家庭设置。

| 页面 | 工作区分栏 | 页眉 |
| --- | --- | --- |
| 今日 | 时间安排、待办、接下来三栏 | 日期与当天的日程数、待办数，逾期数用朱色；右侧「创建」菜单 |
| 日历 | 月格铺满，右侧当日栏 | 年月、前后切换与「今天」；右侧视图切换、筛选、创建日程 |
| 任务 | 清单 + 详情栏 | 未完成数与状态切换；右侧搜索、筛选、创建任务 |
| 笔记 | 清单 + 笔记本身（进入时打开最近一篇） | 篇数与排序；右侧搜索、创建笔记 |
| 助手 | 对话列表、对话、待确认三栏，各有栏头 | 不使用共享页眉 |
| 家庭设置 | 成员与邀请的表格，右侧是基本信息和离开家庭两张卡片 | 家庭名；右侧邀请家人 |
| 标签管理、重复安排、家人生日 | 清单 + 详情栏 | 数量与排序或用途；重复安排带类型切换；右侧创建入口（重复安排没有） |
| 个人中心 | 二级导航（个人资料、设置、提醒、收件箱；还没有家庭时加我的家庭）+ 限宽居中的内容列；退出登录在二级导航底部。个人资料是一张基本信息卡片，同家庭设置：昵称行带「编辑」，在行内改成输入框与取消、保存；用户名行附说明 | 页名 |

- 页眉从左到右依次是页标题、一行摘要和视图切换；摘要先写数量，再写排序或用途，如「4 项 · 按下次发生时间排列」。右侧依次是搜索、筛选和创建；1280 以下搜索框收窄。页标题不截断，放不下时截断摘要。创建按钮是墨色主按钮，带 + 图标，按钮文字写出要创建的对象，如「创建任务」「添加生日」；每页只有一个创建入口。
- 除标题外还有两项以上并列信息的清单，改成对齐的列，上方加一行 `caption` 列标题，如重复安排、家人生日和成员表。标题、说明等列自适应宽度；日期、年龄等短列定宽、右对齐，列宽写进 `theme.layout`。
- 清单行悬停时底色变为 `surfaceSubtle`，行内的「…」也在这时出现。打开中的行用纸色底加 2px 墨色竖条；不用更深的底色，否则朱色日期和弱化文字的对比度会低于 4.5:1。
- 宽屏文字：页眉标题用 `section`，详情栏标题用 `paneTitle`，清单标题用 `bodySm` 常规字重，组名用 `GroupLabel`，次要信息用 `meta`，日期与时间用 `time`。
- 家庭切换从侧栏顶部向下展开，账户菜单从侧栏底部向上展开，都不加遮罩。独立确认居中显示，打开时焦点落在安全按钮上。
- 今日的栏头带去处链接，如「在日历中查看」「全部任务」；待办栏底部可以再添一项；接下来一栏是小月历和未来 7 天。

### 总览

加入两个以上家庭的人有「总览」：今日、日历和任务把他选中的家庭合在一起显示。笔记、助手和家庭设置这些页面仍属于一个家庭。

- 家庭切换菜单最上面是「总览」，下面是各个家庭；不在总览里的家庭注明「不在总览里」，菜单底部可以「调整总览里的家庭」。只有一个家庭时没有总览，界面不变。
- 每个家庭有一枚方形小印章：家庭名的第一个字，描边和字用 `householdMarkColors` 里的一种颜色，按加入的先后分配。圆形是家人头像，圆点是标签，方形才是家庭；印章不用朱色。总览里的日程和任务在清单行的次要信息里带印章，宽屏的日程条和月历小点改用家庭颜色。加入两个以上家庭时，日程和任务的详情都有「家庭」一行，写印章和家庭名，不论从哪个页面打开。
- 总览的今日在页眉右侧（手机在标题下）列出总览里的家庭和「调整」。日历和任务不再列这一行，看和调整都用侧栏顶部（手机顶栏）的切换。总览里的任务只列分给自己的和未分配的，清单底部写「另有 N 项分给家人」并可「显示全部」。宽屏今日的小月历同样只数总览里的家庭和清单列出的任务。
- 两个家庭的日程时间重叠时，后开始的那条下面用墨色小字写「和某家的「某日程」时间重叠」，不用朱色，因为没有东西逾期。
- 宽屏侧栏：总览时顶部切换显示「总览」，下面是今日、日历、任务；一条分隔线之后是当前家庭的名字和「换」，再列笔记、助手和家庭页面。手机底栏不变，笔记和助手打开当前家庭，页头写明是哪个家。
- 在总览里新建时，窗口顶部的「保存到」可以选家庭，默认当前家庭：一枚带印章的小按钮，点开后家庭列在它下方的锚定菜单里，表单不移动。换家庭会清空负责人和标签，已写的内容留下；这一点不在界面上另加说明。
- 日历的月格铺到工作区底部；跨天日程画成横条，一格放不下时写「还有 N 项」。当日栏分全天和时间线两组。
- 笔记清单有置顶时第一组是「置顶」，其余按「最近 7 天」「更早」分组，清单上方是标签一排；行的写法见下文「笔记」。阅读区就是笔记本身。
- 助手的对话列表注明对话仅自己可见，底部是模型配置入口；右栏放待确认的操作和查询依据。模型配置在宽屏上是对话之上的居中窗口（编辑器尺寸），标题栏右侧是「添加」，各项配置以细线分隔成一列；添加、编辑和删除在它之上打开，关闭后回到模型配置窗口。手机上仍是助手的子页面。

### 笔记

笔记是「一页纸」：阅读和编辑是同一页，排版所见即所得。编辑器和存储方言的决定见 [ADR 0002](adr/0002-notes-editor.md)。

- **笔记清单**：有置顶时第一组是「置顶」，宽屏其余分「最近 7 天」「更早」，手机其余放在「其他」一组；没有置顶时与以前一样（手机不分组）。每组内都按修改时间排列，置顶不改变顺序，行里也不另画图钉。宽屏进入笔记页时打开的仍是最近修改的那篇，不因置顶改变。
- **清单行**：标题一行，标签照任务行的样子写在标题旁（最多一枚）。第二行依次是修改时间、清单进度（有清单时写成 `3/8`）、作者，然后是正文开头；有清单的笔记不写正文开头。不在家庭里的作者写作「已离开的成员」。读屏名称在「笔记：标题」后接上置顶、清单进度和标签，如「笔记：周末采购，已置顶，清单 3/8，采买」。行的「…」里是「置顶」或「取消置顶」，然后是删除。
- **标签筛选**：清单上方一排标签，第一个是「全部」，单选，选中后只显示带这个标签的笔记。只列出至少有一篇笔记在用的标签，按家庭标签的顺序；没有笔记带标签时整排不出现，选中的标签不再有笔记用时回到「全部」。手机上横向滚动，滚动区伸到屏幕两边，标签从页边距下面滑过，静止时第一个仍和页面文字对齐；宽屏上折行。筛选和搜索词一样按家庭记在本机。
- **搜索**：占位文字是「搜索标题和正文」，规则和别处的搜索框一样（全角半角、大小写、平片假名都算相同，多个词都要出现，可以分别在标题和正文里）。正文按读到的纯文本找，不找 Markdown 写法。命中在正文里时，行的第二行换成命中处的一小段：前面约 12 个字，后面填到约 40 个字，截断处写「…」；命中的词用 `ink` 半粗体，其余用 `inkMuted`，不用朱色或底色。只在标题命中时，行和平常一样。搜索和标签筛选可以同时用；没有结果时说明找不到什么，按钮清掉搜索和筛选。
- **打开**：点清单里的笔记，打开的就是可以写的文档，没有「编辑」按钮，也没有预览切换。打开时不自动聚焦，手机上轻点页面才放光标，免得一打开就弹出键盘；文字下面的空白也是这一页，轻点就接着最后一行写。键盘弹起、工具栏出现时，正在写的那一行留在视线里；`/` 菜单放不下全部高度时在剩下的空间里滚动。宽屏进入笔记页时在清单旁打开最近一篇；关掉后不再自动打开，阅读区提示从左边选一篇。
- **保存**：停笔约 1 秒、切到别的笔记、关闭、应用转到后台时都会保存。组字期间不保存；只是打开、没有改动的笔记不写回。`Ctrl Enter`（Mac 上 ⌘ Enter）立刻保存。每次改动先存为这台设备上的草稿，保存失败时留着，下次打开先恢复，状态写「未保存」。
- **标题**：页面最上面一行大字就是标题，也是文档的第一行；在标题里回车进入正文开头。标题可以空着，保存时取正文第一行有文字的内容作标题；标题和正文都空时不保存。
- **清单**：存成 `- [ ]` / `- [x]`。点方框只切换勾选，不移动光标、不弹键盘，勾选立刻保存；点文字才进入编辑。清单项里回车接一项，在空项上再回车就退出清单。已勾的项文字划线、变淡。勾选撞上家人的修改时自动合并，不打扰。
- **格式**：手机上，键盘上方有一排工具：清单、列表、小标题、粗体、链接和收起键盘，键盘收起时这排也收起。宽屏没有常驻工具栏。两端都可以直接打 Markdown 写法，也都可以在行首或空格后输入 `/` 打开插入菜单：待办清单、列表、编号列表、小标题、引用、分隔线、表格、代码块、链接，每项右侧浅色写出对应写法，可用 ↑↓、Enter、Esc。表格和链接在窗口里的一步中填写，新表格的表头先写好「列 1」这样的列名。
- **页头**：宽屏栏头写「{作者}写 · {谁} {时间}改过」，作者自己改的只写时间；手机把这一行放在标题上方，保存状态写在这一行的右端，窄窗口的页头只留给窗口名和按钮。宽屏栏头右侧依次是保存状态、置顶、标签两个图标按钮和「…」菜单；手机页头右侧是后三样。置顶按钮在已置顶时显示为按下状态（`surfaceSelected` 底、加粗图标），读屏名称随状态写「置顶」或「取消置顶」；标签按钮读作「标签」。还没保存过的新笔记不显示这两个按钮，第一次自动保存之后出现。保存状态只用文字和小图标（已保存、正在保存…、未保存），不用朱色。「…」里是删除（只对作者和管理员出现，确认仍用居中窗口）和 Markdown 导出：Web 上是「复制为 Markdown」，手机上是「以 Markdown 分享」，打开系统分享面板，面板里可以复制。不在家庭里的人写作「已离开的成员」。
- **标签**：笔记的标签用小标签写成一行，放在标题上方：手机在作者那一行下面，宽屏在正文栏的最上面。标题是编辑器文档的第一行，原生的一行插不进标题和正文之间。点这一行也打开标签选择；没有标签时这一行不出现。标签选择宽屏是锚定弹层，手机是窗口步骤，用「完成」确认，和任务表单里的标签选择一样；管理员在里面仍能「新建标签」，手机上它是标签步骤之后的下一步，建好或取消后回到标签步骤，新标签已选中，按「完成」后立刻写在笔记上。
- **置顶和标签不算修改正文**：置顶全家共用，家人谁都能置顶、取消，也能给任何笔记加减标签。它们点了就保存，不经过正文的自动保存，也不改笔记的修改时间和最后修改人，所以正在写这篇的人不会因此遇到冲突提示，清单顺序也不跳。两个人同时改标签，后保存的为准。保存失败时恢复原样，并在正文上方用小字说明。
- **冲突**：有文字改动的保存撞上家人的修改时，自动保存停下，正文上方出现提示条「{名字}在你写的时候也改了这篇。自动保存先停下，你的内容还在。」。提示条上可以「对照最新内容」（展开后可以「改用最新内容」，放弃这台设备上的改动）或「用我的版本保存」。
- **保存不了**：没有网络或服务器出错时，正文上方用小字说明内容已存在这台设备，回到前台和每隔 30 秒再试；笔记已被删除时说明并提供「另存为新笔记」。
- **权限**：家庭成员都能改任何笔记、置顶和贴标签，删除只限作者和管理员；新建、改名和删除标签仍只限管理员。标签管理页的用量里也数笔记，如「2 个日程 · 3 篇笔记」，删除标签的提示写出笔记数，并说明日程、任务和笔记本身会保留。

设计稿里画了但还没实现的部分记在 [路线图](roadmap.md)。

## 界面用语

同一概念在可见文字和读屏名称里使用同一个词；代码里的技术名称不受影响。

| 概念 | 统一用语 |
| --- | --- |
| 日历中的一项安排 | 日程；「日历」只指页面 |
| 自动重复的日程或任务 | 重复、重复安排；频率设置称「重复规则」 |
| 家庭最高角色与身份交接 | 所有者、转移所有权 |
| 创建与编辑提交 | 创建、保存；上下文已明确时省略对象名称 |
| 个人的到点提示 | 提醒；表单与详情字段称「提醒我」；系统通知权限称「通知」 |
| 按农历的日期与重复 | 农历十月十五、每年农历十月十五；十一月、十二月称冬月、腊月。日文界面写旧暦十月十五日，月日用汉字数字，月历格子里的农历日只写数字（十五、二十一），节气和节日用日文汉字（啓蟄、中秋節），不显示中国的公历节日 |
| 生日系列与其页面 | 生日、家人生日；创建入口称「添加生日」 |
| 只影响这台设备的选项 | 设置；账户资料称「个人资料」，家庭的称「家庭设置」 |

计数使用全角括号，如「逾期任务（3）」。日期复用 [日期工具](../apps/client/src/ui/date-values.ts)，显示为「9月27日」「9月27日 14:30」，非今年加年份；日期选择器保留完整年份。分组已说明日期时，行内只写时间。月历、周视图、日期选择器与重复星期均从周一开始。

### 弹窗与选择

容器、遮罩、标题、关闭入口和焦点管理统一交给 `AppDialog`；路由窗口复用 `RouteWindow`。共同外观通过基础组件修改，并验证所有使用场景。新建与编辑窗口用 `HouseholdContextNote` 说明保存到哪个家庭；从总览打开的新建窗口改用 `HouseholdTargetField` 让人选择。

| 类型 | 宽屏 | 窄屏 |
| --- | --- | --- |
| 任务、日程与重复安排的阅读 / 编辑窗口 | 常驻详情栏，无遮罩，列表保持可操作，当前条目有选中标记 | 最窄屏使用全屏编辑面板，左上关闭、右上主操作；中间宽度居中，断点由主题定义 |
| 笔记 | 文档在阅读区或详情栏直接编辑：笔记页上占据完整阅读区，从其他页面打开时在详情栏 | 全屏文档，左上关闭，右上是保存状态和「…」；键盘上方是格式工具 |
| 账户与设置 | 个人资料原位编辑，选项用锚定弹层；退出、重命名与邀请等独立窗口居中 | 居中，沿用对应窗口尺寸 |
| 独立确认窗口 | 标准尺寸居中 | 标准尺寸居中 |
| 助手操作、模型选择与查询依据 | 操作内容可在工作区右栏展示；弹层使用共享容器 | 底部面板 |

- 所有删除与结束重复操作用标准尺寸的居中确认窗。宽屏保留原详情栏或编辑栏作为背景，窄屏在同一个窗口内切换到居中的确认内容。取消后回到原入口并保留编辑内容。确认先展示对象及日期（如有），再展示影响或可选范围，警示文案放在操作上方。删除重复条目默认仅删除这一次。Web 将初始焦点放到取消按钮。
- 保存确认等编辑步骤在原窗口切换并保留编辑内容。在清单里点另一项引起的未保存询问，用居中提示窗。
- 固定选项用摘要行打开步骤选择：单选选中即生效，多选用「完成」确认。步骤内不再嵌套步骤，只有笔记的标签步骤例外：它本身就是窗口里唯一能放标签选择的地方，里面的「新建标签」再开一步，关闭后回到标签步骤。步骤里的日期字段可叠加一个标准 `AppDialog`。只有最上层弹窗响应键盘。表单里的小编辑（如标签选择旁的「新建标签」）也这样打开：宽屏是锚定弹层，窄屏是窗口步骤，不在表单里展开，免得窗口矮时被截断。
- 日期选择沿用平台方案：Android 使用系统 Material 3 对话框，时间跟随手机的 12/24 小时设置；iOS 使用原生日历或滚轮；Web 使用 [共享选择面板](../apps/client/src/ui/picker-panels.tsx)。日期标记统一为墨色实心圆表示选中，今天是浅朱底圆（`accentSoft` 底、`accentStrong` 数字），两者重合时为朱色实心圆；朱色数字留给祝日。宽屏月历格子里的今天是朱色实心。
- 全屏弹层使用 `DialogBackdrop` 的模糊与浅遮罩，常驻详情栏除外；锚定菜单使用透明关闭层。系统原生提示与锚定菜单保持各自交互类型。
- 确认按钮安全选项在前、提交在后，放不下时纵向排列；不可逆或收回权限的提交使用危险样式，多步确认只在最后一步使用。单输入框设置窗口保留一个提交按钮，取消走关闭入口。

### 状态与恢复

- 覆盖组件适用的默认、按下、选中、禁用、加载、成功和失败状态；加载时保留操作文字，避免重复提交。状态同时提供文字或形状信息：逾期、紧急写明状态，已完成加删除线并写明「已完成」。
- 加载失败就地说明并提供重试，保留已有内容；提交失败保留输入与恢复入口；未知数量不显示为零。空状态与页面文字左对齐，可附一个下一步操作。
- 收件箱摘要打开详情，接受、拒绝等动作独立触发；后台更新保留已有消息，移动端提供下拉刷新。缺少服务端已读状态时，待处理数量只能称为「待处理」，不能称为「未读」。
- 撤销提示保持可操作，不定时消失；点击页面其他位置时等手势结束后关闭，或离开页面时关闭，避免列表重排影响当前点击。

## 变更与视觉验收

先确定改动属于页面组合、组件能力还是全局主题，再定位共享实现。通用设计决策改变时同步更新本文、实现和相关检查；局部功能细节留在对应实现中。发现规范与实现不一致时，先确认是否属于本次需求，再校正相关部分。

视觉验收检查：

- 颜色与控件用途符合上述规则，主题参数与共享组件保持复用，同类内容的层级、对齐和密度一致。新页面在同一宽度下与它参照的同类页面并排截图对照，确认页眉组成、清单通栏、创建入口和行状态都相同。
- 受影响页面在 320、390、1440 宽度下无水平溢出，导航、表单和主要操作可达；长内容、大字、空数据、加载与失败状态均可用。
- 触控目标、读屏名称、状态语义、键盘焦点和对比度可用。Web 交互变更另读 [无障碍约定](agent/web-accessibility.md)。
- 共享组件变更覆盖受影响页面，布局变更检查实际渲染与截图；弹窗基础组件变更同时回归账户和家庭设置窗口，检查容器、标题、关闭入口与背景样式。
- 原生布局或平台能力变更进行设备验收；Web 检查不能替代真机证据。测试选择、执行与证据报告遵循 [testing.md](agent/testing.md)。

[token 检查](../apps/client/src/ui/__tests__/token-static-test.ts) 与 [对比度检查](../apps/client/src/ui/__tests__/contrast-test.ts) 约束设计实现，保持其断言强度。纯文档修改检查内容、差异和链接即可。

设计依据：[Apple Typography](https://developer.apple.com/design/human-interface-guidelines/typography) 与 [Layout](https://developer.apple.com/design/human-interface-guidelines/layout) 支持清晰层级、字体缩放和自适应布局；[Things](https://culturedcode.com/things/features/) 启发日程与任务集中呈现；[W3C 颜色使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color) 与 [对比度](https://www.w3.org/TR/WCAG22/#contrast-minimum) 支持状态冗余表达和可读性。这些资料提供方法，具体视觉取值属于本项目决策。

未完成的产品意图与验收事项见 [路线图](roadmap.md)。
