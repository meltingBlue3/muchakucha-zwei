# 前端设计规范

本规范用于新增页面、调整组件和审查视觉改动，维护 Muchakucha Zwei 的统一设计语言。适用于 Android、iOS 和 Web；PC 与 App 的设计质量同等重要，分别根据宽屏、触控、键盘和阅读场景组织布局。

本文约定通用规则，不固定具体页面的功能、文案或交互方案。产品需求决定页面行为；本规范决定这些行为如何融入现有界面。

## 设计方向：纸 · 墨 · 朱

安静的工具，带一点家庭的温度。纸色背景承载白色清单面板，墨色写字、也填充主要操作；朱色像本子上盖的一枚印章，只在「今天、现在、逾期、紧急」出现，因为用得少，出现时才有分量。界面里的其他颜色来自家人本身：每位家人固定的头像颜色和标签颜色。

以字号对比、留白和对齐组织信息，而不是卡片和装饰。同类内容合成一组清单，用细线分隔；一屏能看到的内容比一条一卡多一倍。参考 Things、Apple 提醒事项的层级与克制，参考网站或截图用于理解方法，不作为整套替换主题的依据。

## 规范与实现的关系

| 来源 | 职责 |

| [theme.ts](../apps/client/src/ui/theme.ts) | 颜色、字号、间距、圆角、尺寸和动效参数的唯一实现来源，也持有家人颜色和标签预设色 |
| [共享 UI](../apps/client/src/ui/) | 通用外观、状态与组合方式 |

## 色彩与表面

以下数值用于识别当前视觉基线；代码始终引用对应主题 token。token 按用途命名（`primary`、`accent`），不按色名，以后增加深色模式只需另写一份取值。

| 语义 | Token / 当前颜色 | 用法 |
| --- | --- | --- |
| 页面底色 | `canvas` · `#F6F4EF` | 纸色，全局背景、导航栏和侧栏 |
| 内容表面 | `surface` · `#FFFFFF` | 清单组、表单面板、窗口 |
| 正文 | `ink` · `#1D1B18` | 标题、正文和主要图标 |
| 次要文字 | `inkMuted` · `#5F5A52` | 元信息、分组标题、未选中的控件文字 |
| 弱化文字 | `inkFaint` · `#736E66` | 白底或纸底上的日期、数量；不放在 `surfaceMuted` 上 |
| 主操作 | `primary` · `#1D1B18` | 主按钮、创建按钮、选中的筛选胶囊、勾选完成 |
| 朱色 | `accent` · `#C2381C` | 今天、现在线、逾期、紧急；不用于普通操作 |
| 控件边界 | `border` · `#8E887E` | 输入框、勾选圈等需要辨识的边界 |
| 按钮描边 | `outline` · `#D8D3CA` | 次要按钮、未选中胶囊（名称已说明用途） |
| 装饰分隔 | `separator` · `#E5E1D9` | 清单行之间的细线 |
| 按下 / 凹面 | `surfaceMuted` · `#EFECE6` | 行按下、搜索框底色 |
| 选中 | `surfaceSelected` · `#EAE6DF` | 当前导航项、宽屏中正在查看的行 |
| 成功 | `success` · `#2F6B4F` | 已完成、新增的内容 |
| 危险状态 | `destructive` · `#A61B1B` | 错误与破坏性操作 |

浅色背景使用 `accentSoft`、`successSoft`、`destructiveSoft`；朱色浅底上的文字用 `accentStrong`。按下、禁用、链接等状态使用各自的语义 token，避免为单个页面另配近似颜色。

**家人颜色**（`memberColors`）按用户 id 固定分配，同一个人在所有页面、所有设备上是同一个颜色；白字在每个颜色上都高于 5:1。朱色不分给家人。**标签颜色**是内容数据，预设色（`labelColorPresets`）同样不含朱色，避免标签圆点被看成「逾期」。

表面层级靠底色区分：纸色页面上放白色面板，面板之间不加边框。阴影只用于浮在内容之上的东西：窗口、菜单、创建按钮、浮动提示。普通内容保持安静。

## 字体与信息层级

中文跟随系统字体（各平台由 `platform/typography` 提供）。时间、日期和数量用 Inter 的等宽数字（`time`、`numeral` 变体），竖排时数字列能对齐；Inter 缺少的汉字由系统字体补上。Inter 只加载 500 和 600 两个字重，加载失败时回落到系统字体。

页面代码通过 `Text`、`Heading` 的语义变体表达层级：

| 变体 | 字号 / 行高 / 字重 | 适用内容 |
| --- | --- | --- |
| `display` | 30 / 38 / 700 | 主页面大标题（今日的日期、任务、日历） |
| `heading` | 22 / 30 / 700 | 窗口标题 |
| `section` | 17 / 24 / 600 | 面板标题、月份 |
| `body` | 16 / 24 / 400 | 正文、清单行标题 |
| `bodySm` | 14 / 20 / 400 | 辅助正文、页面副标题 |
| `meta` | 13 / 18 / 400 | 清单行下方的地点、状态、标签 |
| `label` | 14 / 20 / 600 | 字段标签、分组标题 |
| `button` | 15 / 20 / 600 | 按钮文字 |
| `caption` | 12 / 16 / 500 | 底栏文字、星期 |
| `time` | 13 / 18 · Inter | 时间列、截止时间、更新日期 |
| `numeral` | 15 / 20 · Inter | 日历格里的日期 |

清单行标题用常规字重，靠位置和字号表达层级；半粗体只给标签、按钮和需要强调的少数地方。`Heading` 的读屏层级默认随字号：`heading`/`display` 为 1，`section` 为 2；窗口里的内容标题在窗口标题之下，写明 `level={2}`。长文本应换行或按内容性质截断；操作名称和关键状态必须可读。保留共享文字组件的字体缩放能力，不通过缩小字号掩盖布局溢出。

## 信息架构与导航

主要去处是 **今日 · 日历 · 任务 · 笔记 · 助手**。

- **手机**：底栏放这五项，选中项只换成墨色和粗线图标，不加色块。顶部一行左边是「家庭名 ▾」，右边是收件箱和自己的头像。点家庭名打开家庭菜单：切换家庭、创建家庭，以及家庭设置、标签管理、重复安排。点头像打开个人资料和退出登录。
- **宽屏（达到 `theme.layout.navigationBreakpoint`）**：没有顶栏。左侧栏顶部是家庭切换，下面是五个去处，再下面是「家庭」分组（家庭设置、标签管理、重复安排），最底部是自己的头像和收件箱。页面自己的内容（如助手的对话列表）放在侧栏中部。
- 五个去处和家庭页面都用 `HouseholdScreen`，它统一负责家庭菜单、账户、底栏或侧栏、访问权变化和页面未找到。切换家庭后停留在同一个去处。
- 家庭设置、标签管理、重复安排是 `subpage`：手机上顶栏只有返回、收件箱和头像，不显示底栏；宽屏保留侧栏并选中该页。页面标题由内容里的 `PageIntro` 给出，顶栏不重复。
- 助手首页在手机上显示底栏；进入一段对话后隐藏底栏，左上角返回助手首页。
- 手机端创建入口是右下角的墨色圆角方形按钮；宽屏放在标题行右侧，用有文字的按钮。`AppShell` 与 `PageIntro` 统一处理位置。

主页面标题区用 `PageIntro`：`display` 大标题、可选的一行副标题（当天概况或生效的筛选），操作放在右侧。

**今日** 是一天的时间线：逾期任务置顶（朱色分组标题）；「全天」放全天日程、今天之前开始的日程和今天到期但没写时间的任务；「时间线」把有时间的日程和任务按时间混排，中间插一条朱色的「现在」线；没有截止日期的任务放「待安排」。后续安排默认收起。宽屏分两栏：左边是今天，右边是待安排和后续安排。

**任务** 页面上直接放状态胶囊（待办、进行中、已完成、全部，首次进入默认待办）；优先级、负责人、标签和重复放在「筛选」窗口里，筛选按钮上的数字只计窗口里的条件。列表按到期时间分组：逾期、今天、之后、待安排。

**日历** 在手机上默认显示选中日期所在的一周，下方按钮可展开整月；下面是选中当天的安排。宽屏是月历加右侧当天安排，月历格子里直接显示日程标题。不在今天时标题行出现「今天」按钮。筛选窗口底部用 `FilterActions`，清除在左、完成在右，宽度比为 1:2；清除取消全部条件，不关闭窗口。

## 界面用语

同一概念在所有界面文字和读屏名称里使用同一个词；代码里的技术名称（如 `events`、`recurrence`）不受影响。

| 概念 | 使用 | 不使用 |
| --- | --- | --- |
| 日历中的一项安排 | 日程 | 事件；「日历」只指日历页面 |
| 会自动重复的日程或任务 | 重复、重复安排；描述频率设置时用「重复规则」 | 周期、周期规则、周期性 |
| 家庭的最高角色 | 所有者 | 家主 |
| 把所有者身份交给他人 | 转移所有权 | 转让 |
| 新建内容的操作 | 创建 | 新增、新建 |
| 表单提交按钮 | 新建时「创建」，编辑时「保存」 | 「创建任务」「保存修改」等加名词的写法 |

计数写作全角括号，如「逾期任务（3）」。列表、详情和消息里的日期用 `formatDate` / `formatDateTime`：「9月27日」「9月27日 14:30」，不是今年时加年份，需要时加「周日」；日期选择器保留完整年份（`formatDateLabel`），因为那里是在确认一个确切日期。列表已经说明是哪一天时（今日、日历当天、任务的「今天」分组），行里只写时间。会话失效统一提示「登录已过期，请重新登录。」

## 布局、密度与形状

- **清单而不是卡片**：同类条目放进一个 `ListGroup`（白色面板、`lg` 圆角），条目是其中的 `ListRow`，之间用 `separator` 细线分隔。分组上方用 `GroupLabel` 写组名和数量。不要给每个条目单独一张卡片。
- 分别设计窄屏与宽屏布局。宽屏利用侧栏、阅读区和详情区组织空间，窄屏通过完整页面和按需展开的面板承载相同能力。清单类页面用 `AppShell width="reading"`（`theme.layout.contentMaxWidth`），需要两栏的页面用默认的 `wide`；正文不随窗口无限拉宽。
- 复用 `AppShell`、`Screen` 和账户布局组件处理安全区、页面边距、滚动与键盘空间。导航断点使用 `theme.layout`，不要混用通用响应式断点。
- 间距从 `theme.spacing` 选取：相关元素靠近，独立内容组留出更大间距（分组之间 `6`）。同一页面保持一致的左右对齐线；时间线里的时间列宽为 `theme.layout.timeColumn`，日程的色条和任务的勾选圈占同样宽度，标题因此对齐。
- 圆角：清单组和面板 `lg`，窗口和底部面板 `xl`，输入框 `md`，按钮、胶囊和头像 `full`，创建按钮是 `lg` 稍大一点的圆角方形。
- 交互目标以 `controlSizes.touchTarget` 为基线；输入框和主按钮复用 `field`、`primary`。视觉图标尺寸与可点击区域分别处理。
- 图标使用 Lucide，线宽 `controlSizes.iconStroke`（1.75），选中的底栏图标加粗；同类动作采用同一图标，图标按钮提供明确的可访问名称。

| 占据整屏的弹层背景 | `DialogBackdrop` |
| 可撤销操作后的提示（如完成任务） | `ActionNotice`，把属性交给 `AppShell` 的 `notice`，浮在内容顶部，含「忽略」和操作按钮；点按页面其他位置（松手后）或离开页面即关闭，不定时消失；关闭后对应内容随之离开列表 |

`ListRow` 的主体打开条目，`leading`（勾选圈、时间列、色条）和 `trailing`（头像、菜单）是与主体并列的控件，不嵌套，Web 上不会出现按钮套按钮。按下主体时整行变成 `surfaceMuted`。两侧控件对齐标题那一行，而不是整行居中：单行条目看起来居中，多行条目向下长，勾选圈、时间和菜单留在标题旁边。放进 `leading` 的文字或图标用 `RowSlot` 包一层，高度与控件一致。

新需求先通过已有组件组合实现；重复出现的视觉结构提取到共享层。业务组件负责领域内容，共享 UI 负责通用外观与状态，平台差异留在适配层。路由和业务文件引用主题值，不直接填写颜色、字号、间距或圆角常量。

### 弹窗的统一入口

新增或修改居中表单、账户面板和确认窗口时，使用 [AppDialog](../apps/client/src/ui/app-dialog.tsx)。调用方提供标题、内容、提交状态、关闭回调和触发按钮引用；可通过 `size="editor"` 使用任务、日程、笔记等阅读/编辑窗口，通过 `footer` 提供正文滚动区域之外的操作区。路由窗口复用 `RouteWindow`，草稿丢弃等确认在同一窗口内切换内容，避免叠加遮罩。标准窗口维持原尺寸，编辑窗口宽度由 `theme.layout.editorDialogMaxWidth` 定义；容器样式不向调用方开放覆盖。需要改变共同外观时修改基础组件，并验证所有使用场景。窗口是白色面板加柔和阴影，没有边框。

窄于 `theme.layout.editorSheetBreakpoint` 时，`editor` 窗口改为参考谷歌日历移动端的全屏面板：左上角关闭，右上角放主操作。表单里的 `FormActions` 会自动把提交按钮交给面板标题栏，取消统一走关闭按钮，调用方不需要分别适配。日程和任务表单采用“图标列 + 无边框内容行”的分组布局，各组之间用 `separator` 分隔，共用 [compose-rows.tsx](../apps/client/src/ui/compose-rows.tsx)。有固定选项的字段（重复、负责人、状态、优先级）显示为一行摘要，点开后在步骤窗口里列出选项：单选选中即生效，多选用「完成」确认。

窗口内的选择控件通过 `useWindowStep`（[window-step.ts](../apps/client/src/ui/window-step.ts)）在同一窗口里打开步骤窗口，编辑内容保持挂载，关闭后焦点回到触发行。日期和时间参考谷歌日历，各平台用各自的方案：Android 用系统 Material 3 对话框（需要 `plugins/with-material3-theme.js` 把应用主题设成 Material3）；iOS 在步骤窗口里显示原生日历或滚轮；Web 用 [picker-panels.tsx](../apps/client/src/ui/picker-panels.tsx) 里的日历面板和按 15 分钟排列的时间列表。日历面板与日历页使用同一套标记：墨色实心圆是选中，朱色是今天，两者重合时是朱色实心圆。步骤窗口内部不能再嵌套步骤；其中的日期字段（如自定义重复的截止日期）改为在上层叠加一个标准 `AppDialog`，不挤占当前窗口的空间。这是“不叠加遮罩”规则的唯一例外。Web 端只有最上层的弹窗响应 Esc 和 Tab。

`AppDialog` 统一拥有背景模糊与遮罩、最大宽度、圆角、内边距、标题层级、关闭按钮、键盘避让和内容滚动；同时处理初始聚焦、Tab 循环、Esc／外部点击关闭、忙碌时禁止关闭，以及关闭后恢复焦点。背景采样由 `AppShell` 的 `DialogBackground` 提供。业务组件不再复制这些结构或独立实现另一套外壳。

居中弹窗、底部面板、家庭菜单和创建菜单这类占据整屏的弹层共用 `DialogBackdrop`（背景模糊加浅遮罩，点按关闭）；锚定在按钮上的下拉菜单（账户菜单、「…」菜单）使用透明的关闭层。

锚定下拉菜单、底部选择面板和系统原生提示属于不同交互类型，不强行套用居中弹窗。确需新增类型时，先定义共享组件与适用边界，再在页面使用。

助手采用独立工作区：`HouseholdScreen layout="workspace"` 允许对话记录独立滚动，输入区保留在可见底部，助手自己的标题行代替家庭顶栏。宽屏侧栏里放会话历史；手机上历史通过标题行打开。操作内容在足够宽的 PC 右栏展示，窄屏使用 `AppDialog size="sheet"` 的底部面板；模型选择、查询依据也使用同一面板类型。该类型沿用弹窗的焦点、关闭、遮罩、滚动和键盘行为，标准确认窗口与全屏编辑窗口保持原有形态。助手首页与对话共用 `AssistantComposer` 输入框；两者可能同时挂载，首页输入框的读屏名称为「开始新对话」，对话中为「发送给助手」。一次提出的多项操作在同一操作面板中逐项列出，每项用勾选行选择是否执行，确认按钮写明数量，如「确认执行（2）」；只有一项时保持单项确认的形态。

修改弹窗基础组件后，运行账户与家庭设置的 Web 回归：覆盖个人资料、退出确认、编辑和邀请窗口，并比较容器、标题、关闭按钮与模糊背景的实际渲染样式。功能测试与视觉一致性检查都需通过，不能用各页面“看起来接近”的样式替代复用。

确认窗口在所有宽度下都用标准尺寸的居中窗口，不随编辑窗口变成全屏面板：只做确认的路由窗口传 `size="standard"`（家庭设置的操作窗口默认如此），编辑窗口内切换到的确认内容（草稿丢弃、重复范围、重复安排的保存和结束）也同时切换为标准尺寸。确认窗口统一用 `ConfirmActions`：安全选项在前，提交选项在后；两个标签放得下时并排，放不下时上下排列。删除、移除、撤销、离开、降级、丢弃草稿等不可逆或会收回权限的提交，使用 `destructive` 样式（`destructive` / `destructivePressed` 填充），不使用墨色主按钮；多步确认只有最后一步使用危险样式。只有一个输入框的设置窗口（个人资料、家庭名称、邀请家人）只放一个提交按钮，由关闭按钮负责取消。

按钮都是胶囊形：主按钮墨色填充、白字；次要按钮白底、`outline` 描边、墨色字；危险按钮 `destructive` 填充。纯文字链接带下划线。按下反馈分两类：纯文字链接和标签胶囊变淡；行、格子、卡片和图标按钮改变背景色（`surfaceMuted` 或 `surfaceSubtle`），主按钮与实心胶囊换成对应的 `Pressed` 颜色。键盘焦点在 Web 上是按钮外圈的朱色描边，不改变布局。

新建与编辑窗口用 `HouseholdContextNote` 说明内容保存到哪个家庭。

每个可交互组件应覆盖其适用的默认、按下、选中、禁用、加载、成功和失败状态。主要操作视觉突出，次要操作层级稳定；加载时保留可识别的操作文字，避免重复提交。状态不能仅靠颜色表达：逾期同时写「逾期」，紧急写「紧急」，已完成的任务加删除线并写「已完成」。

列表、详情和表单应考虑长内容、空数据、加载与失败恢复。加载失败统一用 `LoadError`：说明原因并就地提供「重试」，已有内容继续显示在下方；提交失败用 `Banner`；空数据用 `EmptyState`，与页面文字左对齐，可附一个下一步操作（如「清除筛选」）。加载中的未知数量不能伪装成真实的零；失败后保留可恢复的输入与操作入口。视觉调整应保留既有业务语义与可访问性。

## 设计变更流程

1. 确定改动属于页面组合、组件能力还是全局主题；找到对应共享实现后再编辑。
2. 优先组合现有 token 与组件。确需新增 token 时，按用途命名，并检查是否已有等价语义。
3. 修改共享组件或主题时，检查所有受影响的使用场景，尤其是列表、编辑与账户布局，避免只让当前页面成立。
4. 若需求改变通用设计语言，在同一改动中更新本文、实现和相关检查；记录变更理由及影响范围。局部功能调整无需扩写为全局设计规则。
5. 完成下列验收后，报告实际检查结果与尚未验证的平台。

## 验收清单

- [ ] 颜色、字体、间距和圆角来自主题；同类组件的外观与状态一致。
- [ ] 朱色只出现在今天、现在、逾期和紧急；主操作是墨色。
- [ ] 主次操作清楚，页面对齐与内容密度一致；新增样式有明确用途。
- [ ] 320、390、1440 宽度下检查受影响页面：无水平溢出，导航、表单和主要操作可达。
- [ ] 检查长标题、多行文字、空数据、加载及失败场景；字体缩放后关键内容仍可操作。
- [ ] 键盘、读屏名称和状态语义可用；文字与控件对比度符合现有无障碍检查。
- [ ] 共享组件或交互变化运行相关客户端测试；布局变化运行相关 Web 检查并查看截图。对照 [UI 测试配置](../playwright.ui.config.ts) 与现有 `e2e` 用例选择覆盖范围。
- [ ] 原生布局或平台能力变化进行相应设备验收；Web 测试和打包通过不能替代真机检查。

现有 [token 检查](../apps/client/src/ui/__tests__/token-static-test.ts) 和 [对比度检查](../apps/client/src/ui/__tests__/contrast-test.ts) 是设计约束的一部分，不能为通过临时样式而降低断言。纯文档改动只需检查差异和链接。
