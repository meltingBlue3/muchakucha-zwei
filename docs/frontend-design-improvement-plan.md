## 检查范围与结论

初始审查覆盖今日、任务、日历、笔记、家庭入口、家庭设置、标签管理，以及任务/日程表单、详情和共享日期控件。下表保留改造前的问题与目标，实际完成情况以上方进度为准。收件箱已在上一轮调整，不重复设计。

初始审查基于页面结构和交互实现，当时未启动应用或截图。三批实施已补充任务、日程、笔记、标签、家庭入口、重复安排和今日分组在 320/390/1440 宽度的浏览器检查和截图；原生软键盘遮挡和大字体表现仍需实际核实。不将未检查的页面视为已经通过设计验收。

主要问题是列表内容过重、常用操作和次要选项层级接近、部分页面沿用不同的导航和表单组织方式。保留现有暖白、珊瑚红和字体体系，优先改善阅读和操作顺序。

## 窗口优先的交互方案

用户补充要求：能以窗口完成的操作优先使用窗口，包括新建和详情；任务详情需要重新设计。本节覆盖上表中仍以独立页面描述的方案，任务详情提升到第一批。

| 内容 | 展示方式 |
| --- | --- |
| 任务、日程、笔记的新建、详情、编辑 | 在当前列表、今日或日历上方打开窗口，关闭后回到原位置 |
| 标签新建/编辑、家庭创建/重命名、邀请、成员操作、筛选、重复安排详情/编辑 | 使用窗口；保留权限与必要的确认步骤 |
| 今日、任务列表、日历、笔记列表、家庭设置、收件箱 | 保留为主要页面，承载浏览和导航 |

窗口统一复用 AppDialog。复杂内容的宽度、滚动正文和底部操作区等能力在共享组件定义，并验证现有收件箱、账户和家庭设置窗口；不在业务页面复制另一套容器。手机端保持窗口交互，按可用高度滚动并避让键盘，长笔记也不能因固定小高度而难以阅读或编辑。若需更宽的阅读窗口，应采用共享的语义化尺寸能力并补充设计规范。

交互约定：

- 从任务列表、今日或日历进入时保留原页面、筛选、日期和滚动位置；关闭回到原入口。保存后更新相关内容，避免整页重载。
- 详情进入编辑在同一个窗口内切换内容，不叠加多个大窗口。编辑保存后回到更新后的详情；取消编辑也回详情，未保存草稿按既有规则保留。
- 重复规则配置、影响范围选择、删除确认等使用窗口内的下一步内容，完成或取消后返回上一层；不叠出多层遮罩。系统日期选择器遵循平台行为。
- 保留可直达的新建、详情与编辑路由。直接打开或刷新时加载所属家庭的基础页面并打开对应窗口；没有站内历史时关闭返回该资源列表。不能只靠某一页的临时状态承载详情。
- 浏览器返回、Android 返回、关闭按钮和 Esc 遵守同一层级；内部编辑/确认返回上一层，最外层才关闭。提交期间禁用重复提交与关闭。
- 关闭新建/编辑不等于丢弃草稿；再次进入恢复原内容，显式“丢弃草稿”才清除。保留部分创建成功后的标签重试，避免重复创建。
- 窗口内呈现加载、失败重试、版本冲突和资源已删除状态。已失去家庭访问权时退出受限内容并显示既有访问变化界面。
- Web 保持单一有效模态层、焦点循环和关闭后焦点恢复。若触发条目已被删除或筛掉，焦点落回所属列表的稳定入口。

## 任务详情窗口布局

当前详情把多个状态按钮放在基本信息前面，内容更像字段清单。改为围绕“这是什么任务、什么时候做、谁来做、现在能做什么”组织。

从上到下：

1. **窗口栏**：“任务详情”和关闭按钮，复用统一容器；窗口内不重复显示个人中心或收件箱入口。
2. **任务标题**：完整显示，允许换行；下面用轻量状态文字标明待办/进行中/已完成/已取消，异常优先级与逾期才加强调。
3. **关键信息区**：截止时间、负责人、优先级、重复安排。宽屏可两列，窄屏按行排列；无日期写“未设置”，无负责人写“未分配”。重复任务说明正在查看的这一次日期，避免与整个系列混淆。
4. **描述区**：独立阅读区域，正文优先，支持长内容滚动；没有描述不放大块空面板。
5. **标签区**：轻量展示，可换行，不与状态徽标混排。
6. **底部操作区**：未完成时以“标记完成”为主要按钮，“编辑”为次要按钮；“开始处理/退回待办”等放入次要操作入口。已完成时改为“标记未完成”；已取消时不显示完成按钮，按现有规则提供编辑/恢复入口。有权限的删除入口放入次要操作并经过确认。

底部操作区在长内容下仍可达，正文滚动不遮挡按钮。状态改变失败就地显示错误并保留详情；成功后更新详情与背后的列表，继续保留已有撤销能力。对重复任务进行编辑/删除时沿用既定的“这一次/后续”范围流程，不因窗口改造而默认作用于整个系列。

## 跨页面先处理的细节

1. **刷新反馈**：今日每次重新加载都会隐藏正文；笔记搜索框会随 loading 消失，其他页面又可能同时保留旧内容和加载提示。统一初次加载与后台刷新：只有首次加载使用占位，已有内容刷新时保留；失败提示说明仍在显示上次结果并提供重试。已确认失去访问权时仍必须移除受限内容。
2. **输入与键盘焦点**：Web DateField 明确设置 `outline: none`，未在该组件内提供替代焦点样式。实施时补齐可见焦点并实际验证。部分旧筛选使用 radio 但只设置 selected，需统一 checked 语义与键盘行为。
3. **文案一致性**：统一“日程/事件”“重复安排/周期规则”等面向用户的称呼；清理邀请链接旧文案。技术字段名不必随界面文案改动。
4. **真实点击区域**：紧凑的是排版，不缩小共享触控基线。颜色选择、筛选和行内按钮检查实际点击区域及相邻区域，不仅依赖 hitSlop。

## 建议实施顺序

1. 第一批：共享窗口能力、任务新建/详情/编辑窗口、任务详情重排、任务行与筛选。用任务完整流程验证窗口导航、草稿、直达链接和冲突处理；同步日期焦点与加载反馈。
2. 第二批：日历布局、日程新建/详情/编辑窗口。先用 320/390 宽度确认选择日期、填写和提交的完整流程，再补宽屏布局。
3. 第三批：笔记新建/详情/编辑窗口、今日分组、笔记列表、标签管理与家庭相关窗口。邀请旧文案属于小修，可在第一批一并处理。

每批单独提供可查看的页面和检查结果。已有草稿、冲突处理、成员权限、重复安排语义均作为回归约束。

## 验收方案

- 在 320、390、1440 宽度比较有内容和空状态；包含长中文/英文标题、多个负责人、多标签、几十项数据，检查横向溢出和主要操作可达性。
- 用固定样例比较改动前后任务列表首屏可读条目数、从今日进入完整分组的路径、从日历选择未来日期并查看安排的路径；缩减装饰不能牺牲可读字号或触控区域。
- 检查过滤条件是否始终可见、可清除；新建、编辑、草稿恢复、校验失败是否能定位到对应字段。
- 检查首次加载、后台刷新、离线失败、权限丢失、完成撤销和并发编辑冲突。
- 从列表、今日、日历打开窗口并关闭，原滚动位置、筛选和日期保持；验证直接访问/刷新链接、浏览器前进后退、Android 返回以及没有历史时的关闭落点。
- 验证详情→编辑→保存/取消、重复范围选择和删除确认，不产生叠层或丢失草稿；长描述、长笔记和软键盘下操作区可达。
- Web 检查焦点可见性、Tab 顺序、弹窗关闭与焦点恢复、读屏状态和对比度。
- Android/iOS 真机检查大字体、键盘避让、日期选择和下拉刷新；Web 通过不能代替这一步。
- 实施后按改动范围运行客户端测试和浏览器回归，分别报告模拟 API 的界面检查与真实 API 流程，失败修复后重跑相关用例。

## 参考与适用边界

- [Material 列表指南](https://m1.material.io/components/lists.html)：同类内容适合通过连续列表组织。采用紧凑行是本项目的设计建议，不是要求所有卡片改成列表。
- [Material 自适应布局](https://m3.material.io/foundations/layout/canonical-examples/overview)：提供列表与详情等宽屏组织方式。日历在宽屏并排展示月历与当日日程，是对本项目的应用判断。
- [W3C 可见焦点技术](https://www.w3.org/WAI/WCAG22/Techniques/css/C45)：键盘操作需要可见焦点；可用 `:focus-visible` 提供指示。日期控件最终效果仍需浏览器验证。
