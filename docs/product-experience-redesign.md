# Muchakucha Zwei 家庭协作体验改版

日期：2026-09-14。依据：当前客户端路由、今日页、日历、任务、笔记及家庭管理实现。以下是基于代码走查的产品判断，尚未经过真实家庭访谈或可用性测试。

## 1. 产品目标

让家庭成员用很少的操作回答三个问题：今天有什么安排、哪些事需要我处理、如何把一件事交代给家人。移动端优先，保留温暖克制的视觉风格。

主要场景：早上看接送和预约；临时记录采购、家务；查看家人的分工；保存长期共用的信息。管理员操作属于低频维护，不应占据日常首页。

## 2. 现状与取舍

| 当前体验 | 影响 | 改版决策 |
| --- | --- | --- |
| 首页以七个功能入口为主 | 进入家庭后还要选择功能，才能看到实际安排 | 家庭入口直接展示今日概览 |
| 各列表缺少共同导航 | 切换功能依赖返回或重新进入家庭 | 五个常驻底部入口 |
| 今日同时展开远期任务 | 当前行动被长列表挤走 | 今天优先，后续安排默认收起 |
| 创建入口主要位于各功能列表 | 临时记事需要先找到模块 | 今日直接进入任务、日程、笔记创建 |
| 家庭切换只有小箭头实际可点 | 点击家庭名称没有反馈，读屏操作也不一致 | 整个家庭名称区域是可访问按钮 |
| 标签、周期规则与日常内容同级 | 新成员需要先理解管理概念 | 集中到家庭页，保留明确入口 |

保留现有服务端权限、日期和重复规则语义。此次不引入通知、聊天、积分或位置跟踪等新业务。

## 3. 信息架构

```text
登录 / 接受邀请
  └─ 当前家庭 → 今日（默认落点）
       ├─ 今日：日期、概览、快捷创建、逾期、今日日程、待办、后续安排
       ├─ 日历：日期选择 → 当日日程 → 详情 / 编辑
       ├─ 任务：筛选 → 任务卡片 → 状态 / 详情 / 编辑
       ├─ 笔记：共享内容 → 详情 / 编辑
       └─ 家庭：成员与邀请、标签、周期规则、家庭设置
```

全局个人中心保留在右上角；切换家庭保留在各主页面顶部。底部的“家庭”管理当前家庭，顶部的家庭名称用于切换，两者职责通过文案区分。

五个标签始终采用图标加文字，并有选中状态。标签切换替换当前主页面，不把每次切换压入返回栈。进入详情或创建页仍使用原有页面栈，返回上一级。编辑页不展示主导航，减少误跳转。

## 4. 页面布局

### 今日：行动首页

首屏顺序：顶部标题与个人中心 → 家庭切换 → 日期 → 今日概览与快捷创建 → 待处理内容。概览只显示已成功加载的数据，不把加载中误报成零条。

```text
┌──────────────────────────┐
│         今日视图      个人 │
│ 当前家庭 · 我们的家      ⌄ │
│ 9月14日 星期一             │
│ 把今天安排好               │
│ 2 个日程 · 3 项待办         │
│ [新建任务] 添加日程 记笔记  │
│ 逾期任务                   │
│   任务名称 / 负责人 / 状态  │
│ 今日事件                   │
│   时间 / 事件名称           │
│ 今日待办                   │
│ 查看后续安排（4）          ›│
├──────────────────────────┤
│ 今日  日历  任务  笔记  家庭│
└──────────────────────────┘
```

示意数字仅为布局说明，运行页面使用真实返回数据。现有未设置截止时间的任务仍归入今日待办；后续应拆成“待安排”，避免把无日期误解为今天到期。此项需要同步调整分组及回归测试，不在本次改动中暗改业务含义。

### 日历：围绕选中日期安排

保留现有日历和事件能力。下一阶段把移动端默认视图调整为周条加当日列表，月历可展开；Web 大屏使用月历与选中日期详情并排。切换月份应保留选中日期的明确提示，提供“回到今天”。从选中日期创建时自动带入日期，跨日事件明确展示结束日期。

### 任务：先处理，再整理

保留现有可折叠筛选和任务状态能力。下一阶段常用筛选固定为“待处理 / 我负责 / 全部”，优先级、成员、标签、重复类型进入高级筛选。筛选后始终显示结果数量和清空入口。

建议将“完成”设计为独立明确动作；进入详情再修改“进行中 / 取消”等状态，避免用户误把三态轮换当成勾选完成。该行为涉及现有任务状态约定，本次没有修改。完成反馈应允许恢复，失败保留原内容并就近显示重试；不能用整页错误代替任务列表。

### 笔记：家庭长期记忆

下一阶段增加标题搜索、最近更新排序；置顶能力需要新增存储支持，再提供“常用信息”区域。空态解释适合记录什么，例如采购清单、旅行计划、家电说明，并给出直接创建按钮。避免暗示笔记已经具备附件或协同编辑能力。

### 家庭：低频维护空间

本次集中标签、周期规则、成员与邀请设置。下一阶段在家庭页优先显示成员概览和邀请入口，下方再放分类、重复规则和家庭资料。退出、移除成员和转移所有权继续保留明确后果说明及已有保护流程。

## 5. 关键流程

| 目标 | 新流程 | 验收重点 |
| --- | --- | --- |
| 早上查看安排 | 打开家庭 → 今日内容 | 不需要再点“今日视图” |
| 临时记一件家务 | 今日 → 新建任务 → 填写 → 保存 | 一次点击即可进入已有表单；保存家庭明确 |
| 看接下来有什么 | 今日 → 展开后续安排 | 不离开今日也能查看；可再次收起 |
| 从任务切到日历 | 点底部日历 | 一次点击，家庭不变，选中状态变化 |
| 找家庭管理 | 底部家庭 → 对应管理项 | 高频工作区不再堆叠管理入口 |
| 切换家庭 | 点家庭名称 → 选择 → 当前模块 | 操作区可读屏；不得展示上一个家庭的内容 |

### 创建表单的下一阶段规范

- 必填信息先出现：任务标题；日程标题与起止时间；笔记标题和内容。
- 负责人、标签、重复、高级时间设置按需展开；当前保存家庭始终可见。
- 保存中防止重复提交；字段错误在字段旁说明；网络失败保留输入。
- 有未保存内容时离开，应提供继续编辑与放弃选项。
- 编辑重复事项时明确“本次 / 本次及以后”等现有范围，展示作用说明，再提交。
- 保存成功返回来源页面并刷新对应内容。以上需逐表单实施和验证，不代表已全部落地。

### 首次使用的下一阶段规范

接受邀请后直接进入受邀家庭的今日页；自行创建家庭后显示轻量引导：邀请家人、添加第一条任务。允许跳过邀请。无家庭时清楚区分创建与接受邀请，避免让新用户面对业务列表空白页。

## 6. 跨端、反馈与无障碍

本次底部导航位于滚动区域外，随屏幕保留，利用 AppShell 的安全区域处理系统手势区；Web 复用限宽内容区域。家庭名称允许换行并可收缩，避免挤掉同排的新建入口。按钮触控区沿用 48 的主题令牌。

后续验证覆盖 320 / 390 / 768 / 1440 宽度、大字号、键盘弹出、Android 返回手势、iOS 底部安全区和 Web 键盘。选中状态不能仅靠颜色传递，读屏需读出标签选中和内容展开状态。

加载、空态和错误必须分开：加载期间不显示完成庆祝；筛选无结果给清空入口；数据失败给重试；操作失败保留内容；成员权限变化使用已有访问变化页面。

## 7. 本次交付与后续实施顺序

已实现：默认今日首页、五项底部导航、独立家庭管理页、今日概览与三项快捷创建、后续任务展开收起、家庭名称整体点击及读屏操作。更新已有 Web 测试的导航定位，并新增组件回归测试。

下一阶段 P1：任务完成交互、未设日期任务分组、创建表单渐进展开与离开保护、日历周视图、笔记空态和搜索。每项独立验收后再扩展。

后续 P2：笔记置顶、Web 双栏、家庭首次使用引导。涉及持久化的能力先补 API、数据库和权限测试。

## 8. 验收与衡量

技术验收：客户端类型检查和 Jest；Web 导航与无障碍用例；Android / iOS 实机验证安全区、返回与键盘。数据库相关浏览器测试必须使用显式配置的可丢弃本地测试库。

产品验证建议找 5 个家庭，各完成“查看今天安排、创建采购任务、找到家人的日程、共享笔记、邀请成员”五个任务。记录首次成功率、耗时、误触和求助点。该样本仅用于发现可用性问题，不能证明统计显著的改善。

验收目标：进入家庭到看今日为零次额外点击；主模块间切换一次点击；从今日进入任一创建表单一次点击。创建耗时、任务完成率、次周家庭活跃率需要建立实际基线后再定目标，不能把设计推断当作已验证效果。

## 9. 账户与家庭入口补齐

第二批覆盖登录、注册、个人中心、无家庭引导、创建家庭与成功页、手动输入邀请以及共用认证容器的离线和邀请状态页。

- 登录与注册：手机单栏，桌面品牌说明与表单双栏；密码显示按钮内嵌输入框；规则提示关联各自字段；提交中禁止修改输入。保留邀请目标的登录注册往返路径。
- 个人中心：资料、家庭入口、设备登录三块独立卡片。用户名只读，昵称修改后才启用保存；加载失败可重试，继续编辑会清除过期的成功提示。退出入口降低视觉优先级，保留现有确认流程。
- 无家庭引导：创建和接受邀请两张说明卡片；个人中心始终可达。加载中不闪现引导；网络失败不推断用户没有家庭，可重新加载。
- 创建家庭：一个名称字段，提供示例与长度说明；创建成功后说明邀请家人的入口；进入失败重试不会重复创建，刷新成员关系时直接选中新家庭。
- 邀请：支持键盘提交，禁用自动纠正，并增加返回家庭或登录的入口。邀请令牌处理及接受邀请的权限规则保持原样。
- 通用组件：修复窄屏错误提示溢出、普通背景上的加载指示器可见性，以及主按钮文字配色。

UI 回归命令：`pnpm exec playwright test --config playwright.ui.config.ts`。此配置只启动 Web 客户端并拦截全部 API 请求，不连接数据库。用例覆盖 320 / 390 / 1440 宽度、密码显隐、邀请目标保留、家庭引导路径、昵称保存及 axe 无障碍检查。真实 API 集成、Android / iOS 实机键盘和安全区仍需另外验证。

## 10. 只读审查后的修复

已处理九项审查问题：按路由家庭显示名称与切换选中状态；任务和事件创建后单独重试标签；任务操作错误与加载错误分开；邀请预览支持重试及重新输入；家庭管理页加入登录恢复路径；筛选和日历位置按家庭暂存；任务表单改用只读保存目标；任务、事件、笔记的创建和编辑表单保留草稿；已完成任务不再标记逾期。

草稿与浏览状态仅保留在当前登录的内存中，按家庭、资源和表单隔离，不写入浏览器持久存储。保存成功清除对应草稿；离开页面后重新进入可继续填写。有草稿时 Web 刷新或关闭页面会触发浏览器离开提示；退出登录、关闭应用或确认刷新后不承诺恢复。标签部分失败时也保留已创建记录 ID，返回创建页后只重试标签，不重新创建记录。

新增 `e2e/ux-regressions.spec.ts` 覆盖审查中的浏览器流程；Jest 覆盖草稿隔离与清除、跨页面的部分失败重试和已完成任务状态。这些 UI 用例使用模拟 API，不能替代真实服务端集成及实机测试。
