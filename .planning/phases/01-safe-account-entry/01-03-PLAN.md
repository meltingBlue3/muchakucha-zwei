<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Email client/scanner → Expo link route | Untrusted GET navigation contains a bearer verification secret. |
| Expo route → verification API | Token and optional device proof cross into the mutating boundary. |
| API → PostgreSQL/MailPort | One-time state is consumed and replacement links leave the service. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-04 | Information Disclosure / Tampering | verification links | high | mitigate | Token-free URL replacement, POST-only consume, structured redaction, hash-only DB, single-use/expiry/supersede tests. |
| T-01 | Information Disclosure | resend endpoint | high | mitigate | Generic response shape plus server per-IP/email throttling and equivalent account-lookup path. |
| T-03-01 | Spoofing | same-device continuation | high | mitigate | Separate high-entropy pending proof in SecureStore/HttpOnly cookie; transactionally match before auto-login. |
| T-03-SC | Tampering | dependency supply chain | high | mitigate | No new package installs; all imports are from the Plan 01-01 approved lockfile. |
</threat_model>
