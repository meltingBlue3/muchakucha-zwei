<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Public reset request/link → API | Enumeration-sensitive email and bearer reset secret enter auth use cases. |
| Authenticated client → logout/users-me | Access JWT subject/session controls which durable record may change. |
| Reset transaction → PostgreSQL | Password hash, one-time token, and all sessions must transition atomically. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01 | Information Disclosure | reset request | high | mitigate | Same status/body/processing intent, server per-IP/email throttles, timing-aware integration cases. |
| T-04 | Information Disclosure | reset link/logs | high | mitigate | Hash-only token, token-free URL replacement, redaction, POST consume, expiry/single-use/supersede tests. |
| T-05 | Tampering | password reset transaction | high | mitigate | One transaction consumes token, updates Argon2id hash, and revokes every session; rollback fault test. |
| T-02-05 | Elevation of Privilege | logout | high | mitigate | Derive exact session from signed `sid`; ignore/reject body targeting; two-device isolation test. |
| T-06 | Elevation of Privilege | PATCH users/me | high | mitigate | Guard-derived `sub`, whitelist-only DTO, explicit public response, cross-account and unexpected-field tests. |
| T-05-SC | Tampering | dependency supply chain | high | mitigate | No new installs; approved lockfile only. |
</threat_model>
