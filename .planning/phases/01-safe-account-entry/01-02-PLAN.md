<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Expo/Web form → generated client → API | Untrusted registration input enters the service. |
| API → PostgreSQL | Password/token derivatives and identity constraints become durable state. |
| API → SMTP/Mailpit | A credential-bearing verification link leaves the API process. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01 | Spoofing / Information Disclosure | register endpoint | high | mitigate | Argon2id, generic canonical-email response, per-IP/per-email throttles, unique DB key, focused integration tests. |
| T-04 | Information Disclosure | verification token/mail/logging | high | mitigate | CSPRNG token, SHA-256 persistence only, structured redaction, no token in response/log assertions. |
| T-06 | Elevation of Privilege | registration DTO | high | mitigate | Global whitelist and forbid unexpected fields; public DTO exposes only email/displayName/password. |
| T-02-01 | Tampering | initial schema | high | mitigate | Reviewed committed migration, real FK/unique/CHECK constraints, non-TTY migrate deploy and status gate. |
| T-02-SC | Tampering | npm installs | high | mitigate | Installation depends on the blocking legitimacy approval in Plan 01-01 and uses only its exact pins. |
</threat_model>
